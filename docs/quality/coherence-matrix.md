## Alcance y límites de "verificado"

- **"Verificado" significa lectura cruzada estática** de los artefactos enlazados (regla, DDL/funciones, Java, OpenAPI, pantalla y script de prueba). **No se reejecutó ninguna prueba**, ni SQL, ni `make`, ni Docker, ni navegador. Las cifras de ejecución provienen de [sql-test-matrix.md](../testing/evidence/sql-test-matrix.md) y de los scripts abiertos; no se revalidan aquí.
- Un ID mencionado en Markdown no cuenta. `COHERENTE_VERIFICADO` exige: objeto de BD abierto en la migración vigente (la última que lo redefine), ruta Java abierta, ruta/esquema OpenAPI localizado, pantalla localizada, y al menos una aserción real (script `db/tests/*.py`, test Java o e2e) que ejercite la regla.
- Si la regla sólo se ejerce por la "ruta feliz" y su rechazo/invariante no tiene aserción, el estado es `PRUEBA_FALTANTE`.
- Cuando un renglón tiene más de un problema se asigna el de mayor gravedad (IMPLEMENTACION_INCORRECTA > PRUEBA_FALTANTE > DOCUMENTACION_DESACTUALIZADA) y los demás se anotan en Notas.
- Criterio para DOCUMENTACION_DESACTUALIZADA: el código de error o el objeto canónico citado por la regla ya no existe o no es el que se ejecuta, aunque el comportamiento esté probado.
- No se leyó cada pantalla línea por línea: se localizó el componente que invoca la ruta (greps sobre `frontend/src/screens.tsx` y `App.tsx`) y los e2e que lo recorren.
